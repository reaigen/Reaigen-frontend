# Reaigen frontend UX audit — 2026-08-16

> Historical baseline. The current findings and protected design decisions are
> in `ux-audit-2026-08-18.md`. In particular, the sidebar must not expand or
> collapse on hover; it uses stable breakpoint-based layouts.

## Scope and method

The authenticated Playwright audit discovered real draft and tour routes and
covered collections, both grid modes, the Agent and account surfaces, creation,
all eight settings sections, two draft details, draft media/edit/share/version
panels, virtual-tour playback, saved cameras, and the tour authoring workspace.

- 28 scenarios
- 107 planned responsive states
- 95 states fully measured in the baseline sweep
- 4 widths: 2048, 1440, 1024, and 390 px
- automated checks: screenshots, Axe, target sizes, overflow, keyboard focus,
  headings/landmarks, console errors, page errors, failed requests and HTTP errors
- destructive actions such as save, publish, delete, restore and form submission
  were deliberately excluded

The 12 baseline 3D-state failures were caused by the audit taking screenshots
or injecting pointer input before/against a continuously rendered WebGL frame.
A headed Playwright verification opened the real saved-camera controls with no
runtime or network error. These are automation limitations, not 12 product
failures. The harness now waits for `aria-busy=false`, uses direct Chromium
surface capture for live WebGL, supports headed checks, and can filter scenarios
and viewports for fast iteration.

## Improvements applied during this audit

- increased collection width/density so desktop shows 9 cards above the fold
  instead of 4, while retaining a readable single-column mode
- made collection search/layout controls persistent and clearer
- improved mobile navigation/account targets and restored browser zoom
- replaced ambiguous “new creation” copy with “new concept/listing” wording
- reduced the floating Agent launcher footprint on ordinary desktop widths
- added intentional missing-cover treatment and accessible decorative avatars
- added tour `main`/H1 semantics and upload-input labels
- raised adjustment-slider readout/reset targets to 36 px desktop and 44 px mobile
- instrumented every audited sidebar, panel and camera state with stable test IDs

The findings below preserve the baseline evidence. A second remediation pass on
2026-08-17 also completed the high-confidence portions of A2–A5, A7 and
U1–U7: visible staged/slow 3D loading and recovery, cacheable SOG delivery,
larger camera/editor targets, clearer camera labels and contrast, readable tour
editor typography, labeled settings controls, a useful Agent empty state,
compact empty seller cover, and a two-action mobile draft footer with an
accessible overflow sheet.

Focused verification after that pass covered 11 affected responsive states and
the known two-camera viewer/editor route. All completed with zero Axe
violations, overflow, runtime/network findings, or dialog focus escapes; the
camera states also recorded zero undersized targets. The full baseline remains
the source for the broader product backlog below.

## Aesthetic and graphic-design findings

### A1 — P1 — Missing tour covers make the product look unfinished

The tours collection is dominated by repeated grey gradient placeholders. The
status and “open” pills repeat on every card, increasing visual noise while the
most important differentiator—the property—has no useful image. Use a generated
tour frame or listing hero as a fallback, retain one compact status treatment,
and show the open action on hover/focus on desktop.

Affected: tours collection at all widths; concepts with missing covers.

### A2 — P1 — Agent empty states are visually inert

Opening Agent creates a large, almost entirely blank panel with one paragraph or
no centered starting content; suggestions sit at the bottom, disconnected from
the empty space. Add a compact contextual starter block near the visual center:
current object, 2–3 high-value actions and one example prompt. Keep the composer
anchored at the bottom.

Affected: collection Agent and contextual draft Agent, desktop and mobile.

### A3 — P1 — Tour-authoring typography is below a comfortable working size

The scene graph and inspector use many 8–10 px labels, badges and values. The UI
looks precise but becomes visually fragile on laptop-density screens and while
working over a detailed splat. Raise secondary text to 11–12 px, reserve 9–10 px
for nonessential counters, and slightly increase panel contrast behind text.

Affected: scene graph, inspector, transform tools, splat editing and cameras.

### A4 — P2 — Draft detail has too many competing control surfaces

On desktop the large gallery, back capsule, 3D CTA, horizontal action capsule
and floating Agent launcher all compete. On mobile, gallery controls, status
chips, tour actions and a sticky three-action bar occupy much of the first
screen. Establish one primary action per breakpoint and move secondary gallery
and version actions into an overflow menu.

Affected: draft detail, especially 390 px.

### A5 — P2 — Seller-profile cover area has weak information value

The large empty title-image block consumes the most prominent part of the form,
although most users need the contact and identity fields first. Show a compact
preview/uploader until a cover exists, then expand when populated.

Affected: Settings → Seller profile.

### A6 — P2 — Navigation rail is elegant but overly compressed

At standard desktop width the brand is reduced to “Re” and navigation labels
are very small. It is visually clean but less immediately recognizable. A
slightly wider default rail or hover expansion would preserve content width
while improving orientation.

Affected: all desktop app-shell pages.

### A7 — P1 — Expanded camera controls are too low-contrast and cryptic

The unified translucent material is consistent between preview and editing,
but most row actions, disabled states, dividers and labels are grey-on-grey.
The second camera name truncates to “K...” while six adjacent icons retain
space, and the “Saved” status visually resembles a disabled button. Give names
more width, separate status from actions, raise text/icon contrast, and reveal
secondary reorder/delete actions on row focus or hover.

Affected: full saved-camera editor and authoring camera panel.

## UX and ergonomic findings

### U1 — P0 — 3D startup gives insufficient progress and recovery feedback

First usable frame varied from roughly 30 seconds to more than 120 seconds for
the same local tour. During that period the screen shows the Reaigen mark and an
indeterminate line, without download/decoding/upload stage, percentage, size,
or a meaningful retry threshold. This can be perceived as a frozen product.

Add staged status (“Downloading”, “Preparing scene”, “Starting renderer”), show
bytes or percentage when available, surface a slow-load message after 10–15
seconds, and offer retry/back after a bounded timeout. Cache the tour asset
between viewer/editor transitions where possible.

Affected: tour viewer, saved cameras and `/create/tour/[id]`.

### U2 — P1 — Camera selection dots are far below ergonomic target size

The automated headed camera check measured saved-camera controls at 18×18 and
28×18 px. The dots are difficult to acquire and do not communicate camera names.
Keep the visual dots but give each a minimum 36×36 desktop and 44×44 touch hit
area; show the camera label on hover/focus and keep the current index visible.

Affected: camera preview and collapsed camera bar.

### U3 — P1 — Tour editor concentrates too many small icon-only actions

The authoring toolbar, node visibility, camera, transform and reset controls
produce the largest repeated real target-size cluster. Icon-only controls rely
on hover titles, which do not help touch users. Group tools by task, use 36 px
minimum desktop hit areas and 44 px mobile hit areas, and keep a persistent
label for the active tool.

Affected: tour authoring workspace at every width.

### U4 — P1 — Accessibility issues repeat systemically

The baseline found 72 Axe violations across successfully measured states:

- color contrast in 39 states, led by the collapsed Agent label and success text
- missing form labels in 17 states, especially media/file inputs and settings
- unnamed buttons in 6 states
- invalid ARIA attribute values in 4 states
- content outside landmarks in 4 states
- disallowed roles in 2 Agent states

Fix shared primitives first: AppShell/Agent, Button/IconButton, upload controls,
Switch/Select and success/status colors. This will remove findings across many
screens at once.

### U5 — P1 — Full-screen tour surfaces lack document structure

The headed saved-camera state had no `main` landmark and no level-one heading;
Axe also found viewer content outside landmarks. Keep the visual UI unchanged,
but wrap the viewer in `main` and add an accessible H1 (it may be visually
hidden) using the tour name.

Affected: virtual-tour viewer and saved-camera editor.

### U6 — P2 — Mobile draft detail has action duplication and obstruction risk

“Open”, “Editor”, gallery/version tabs and the sticky Edit/Share/3D bar are all
visible within a short vertical distance. The sticky bar overlays the content
area and makes the tour card feel crowded. Use a single sticky primary action
plus a “More” menu, and reserve bottom safe-area padding equal to the bar.

Affected: draft detail at 390 px.

### U7 — P2 — Switches and Agent suggestion chips have shallow hit areas

Settings switches measured 44×24 px and Agent suggestion chips about 32 px
high. They meet a minimal 24 px accessibility threshold but are less comfortable
than the rest of the touch-oriented UI. Make the complete setting row clickable
and raise mobile suggestion chips to 44 px.

Affected: privacy, notifications, Agent settings and Agent panel.

### U8 — P2 — Search and layout controls consume a full row before content

The revised sticky collection toolbar is clear and usable, but on smaller
desktop/tablet widths it remains visually heavy. Keep layout controls on desktop,
hide them on mobile, and collapse them into a compact menu on tablet if card
content drops below two complete rows above the fold.

Affected: concepts and tours collections.

### U9 — P2 — Authoring can abort and restart the scene asset request

One headed authoring-camera run recorded an aborted `scene.sog` request while
the viewer still recovered and rendered. Confirm whether renderer remounts or
camera-mode transitions start duplicate asset requests; avoiding redundant
downloads would improve the highly variable startup time.

Affected: tour authoring workspace.

## Hard failures and blocked flows

### Confirmed product failures

No P0 runtime failure was confirmed in the read-only sweep. Across the 95 fully
measured baseline states there were:

- 0 console/page/network/HTTP error findings
- 0 horizontal-overflow states
- 0 dialog focus escapes in the 24-stop keyboard probes

The headed saved-camera flow loaded, accepted the real pointer click and opened
without a runtime/network error.

One separate headed authoring-camera run recorded an aborted SOG request, then
recovered and rendered successfully; it is tracked as a performance/reliability
risk rather than a blocked flow.

### Reliability risks that can become blocked flows

1. **P0 perceived freeze:** 3D load duration and lack of staged feedback can
   make viewer/editor/camera entry indistinguishable from a hard hang.
2. **P1 assistive-technology blockers:** unnamed controls, unlabeled inputs and
   invalid ARIA can make specific actions unavailable to screen-reader users.
3. **P1 missing recovery contract:** the loading experience needs a visible slow
   state and bounded retry/back path even when the renderer has not thrown.

### Automation limitations kept out of product totals

- Headless Chromium can stall native pointer injection and normal screenshots
  against the continuously rendered WebGL canvas; headed Chromium succeeds.
- The original mobile settings audit searched for desktop tabs although the UI
  correctly switches to a select. The harness now supports both controls.
- Scene graph and inspector can already be open, so absence of an “open” button
  is no longer treated as an unavailable state.

## Recommended implementation order

1. Add staged 3D loading, slow-load recovery and transition caching.
2. Increase camera/editor targets and raise tiny authoring typography.
3. Fix shared accessibility primitives and tour landmarks/H1.
4. Simplify mobile draft actions and improve Agent empty states.
5. Improve generated cover fallbacks and reduce repeated card chrome.
6. Compact the empty seller-cover treatment and refine desktop navigation.
