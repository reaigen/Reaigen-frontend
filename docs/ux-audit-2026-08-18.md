# Reaigen frontend UX and aesthetic audit — 2026-08-18

## Purpose

This is the current working audit for the production web frontend. It separates
hard failures, ergonomics, and aesthetics so a technically valid screen is not
mistaken for a finished design. It also records protected decisions that must
not be removed by a generic consistency pass.

The visual review uses the current web product together with:

- the original `Reai-web-ui-components` direction;
- the supplied `DESIGN_WEB_MINDMAP` references;
- iOS commit `1c73946`;
- visionOS commit `7239c64`;
- the product rules in `design-language.md` and `design-ecosystem.md`.

The ecosystem is related by hierarchy, material restraint, image priority,
radius roles, and interaction quality. Web, iOS, and visionOS should not be
pixel-identical.

## Automated coverage

Authenticated Playwright runs used live data on `0.0.0.0:3056`. Each scenario
starts in a clean browser context to prevent view preferences from leaking into
later screenshots. Checks include Axe, control target geometry, horizontal
overflow, nested scroll owners, keyboard focus containment, busy regions,
console/page/network errors, and screenshots.

- core collections, creation, and default settings: 8 desktop/mobile states,

Tour routes use a CDP visual/renderer path. Next.js development navigation can

reporting that tooling condition as a product failure.

## UX and ergonomic findings

### U1 — P1 — Internal tour-authoring controls remain too small

The five authoring states contain 142 controls below the audit's preferred
target. Most are compact transform, graph, inspector, and pruning tools. This is
the largest remaining ergonomic cluster, but it is lower product priority than
the customer-facing detail, sharing, media, and delivery flows.

Improve this by expanding invisible hit regions first. Do not enlarge every
visible icon or turn the bottom toolbar into a heavier capsule.

### U2 — P1 — Reconstructed scene quality dominates editor perception

The Spark renderer is ready and error-free, but the current Colosseum scene is
visibly blurred in viewer and authoring screenshots. That makes a stable editor
feel broken. The next investigation must separate source reconstruction quality,
initial camera placement, render profile, and progressive-quality settling from
panel design.

### U3 — P2 — Agent settings are text-heavy on mobile

The Agent permission model is clear but the first mobile card contains a long
policy explanation before the next action. Use progressive disclosure for the
full processing description while keeping the concise privacy promise visible.
Do not replace the content with unexplained icons or marketing copy.

### U4 — P2 — Empty cover states still weaken collection scanning

Concept and tour cards without media use the correct quiet gradient and retain
their title/status, but repeated placeholders still make the product look less
finished. Prefer a generated tour frame or listing hero when one exists. Never
hide the title behind an icon-only empty state.

## Aesthetic findings

### A1 — P1 — The remaining visual debt is concentrated, not systemic

The customer-facing core now has a coherent editorial structure: two equal
desktop cards, image-led detail/gallery layouts, stable navigation, black for
the primary action/current selection, and restrained white panels. The correct
next step is local refinement, not another global normalization pass.

### A2 — P1 — Spatial editor surfaces still compete with the scene

The scene graph, inspector, top actions, bottom tool rail, axis indicator, and
optional pruning panel can all be visible simultaneously. Their individual
materials are restrained, but together they form six focal zones. Contextual
tools should appear only for the current task; the scene and active camera must
remain visually primary.

### A3 — P2 — Sharing is intentionally denser than versions

Sharing has real configuration density and benefits from grouped sections,
circular selectors, and one full-width creation action. Versions is sparse when
only two versions exist. Do not add decorative cards to fill that space or force
both panels to have the same internal rhythm simply because they share a shell.

### A4 — P2 — Media selection may change composition, but not typography

The selected photograph uses a larger summary region while unselected assets
remain equal grid tiles. This contextual asymmetry is useful. Titles, metadata,
and action labels must keep one type scale across the selected summary and tile
grid; the feature image must use the full-quality source so it does not look
softer than adjacent thumbnails.

### A5 — P2 — Hover should reveal hierarchy, not invert meaning

Image overlay actions may transition from translucent white to black, matching
the established “Edit gallery” interaction. Status chips and non-actions should
not use that inversion. Removing hover entirely is not a solution; hover and
focus need the same intentional elevation and contrast.

## Protected baselines — do not regress

- Keep the concepts and tours collections at two cards per desktop row.
- Keep the full labelled sidebar on wide screens, a stable icon rail with the
  `Re` wordmark on smaller desktop/tablet widths, and bottom navigation on
  mobile. Never auto-collapse the sidebar on hover.
- Keep the original unboxed navigation icons. Do not add bordered slabs around
  navigation groups or squash labels/icons to manufacture compactness.
- Keep selection controls as rounded tracks with a black active segment. Keep
  sharing check selectors circular; a checkbox is not a radio and vice versa.
- Keep the Agent launcher circular. Do not restore a wide “Agent” capsule.
- Keep the detail action rail aligned as one group, with the primary 3D action
  on the same baseline as gallery/edit/share/version actions.
- Keep the gallery icon semantically a gallery/grid action. Do not use a
  fullscreen icon for an action that opens the gallery overview.
- Keep gallery overview as the first action from the detail mosaic; fullscreen
  photo viewing remains a separate action inside the overview.
- Preserve the wide parameter editor and its current information hierarchy.
- Loading may use the Reaigen mark and progress rail, but no generic visible
  “Loading” label.

## Implementation order

1. Preserve the now-clean customer-facing core and use the automated screenshot
   matrix as a regression gate.
2. Investigate reconstruction/camera/render quality before restyling the 3D
   canvas UI.
3. Expand invisible authoring-tool hit regions and reduce simultaneous panels.
4. Add progressive disclosure to the long Agent settings explanation.
5. Improve real-media fallback selection for missing concept/tour covers.
